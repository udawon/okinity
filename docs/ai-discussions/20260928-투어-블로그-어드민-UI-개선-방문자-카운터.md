## 1. 현황 분석

### 1.1 공개 페이지 (실측)
- 투어·블로그 본문 폭 1248px — `Container` 가 `max-w-container` 를 항상 붙여 페이지의 `max-w-3xl`/`max-w-2xl` 를 덮는다(클래스 병합 버그).
- 투어 본문은 `whitespace-pre-wrap` 한 덩어리. 운영자가 `★제목★`, `*`, `-`, `!…!`, `@`, `1.`, `A -> B` 표기를 일관되게 쓰지만 모두 같은 글자 크기로 출력된다.
- 메타 라벨 `text-[11px]` — DESIGN.md 최소 12px 위반.
- 블로그 글은 사진 9~11장이 전체 폭으로 세로 나열(글 1개 ≈ 8,800px), 글 끝에 투어·예약·다음 글 연결이 없다. 제목 앞 `260924` 가 날짜와 중복.

## 2. 문제 정의
1. (객관) 폭 버그·11px — 가독성 저하, 표준 위반.
2. (객관) 본문 표기법이 서식으로 반영되지 않아 정보 위계가 없다.
3. (구조) 시안의 요약 타일·진행 순서·예약 카드는 "칸이 나뉜 데이터"를 전제로 하는데 실제 데이터 대부분은 본문 글 속에 있다 → 값이 없을 때의 표시 규칙이 필요.
4. (운영) 블로그 → 예약 동선 부재.
5. (운영) 어드민 첫 화면에서 할 일·방문자 추이를 알 수 없다.

## 3. 해결 방안

### 방안 A — 모든 정보를 새 입력 칸으로 구조화(시안 그대로)
- 장점: 표현 자유도 최대.
- 단점: 14투어 × 3언어 재입력. 원님(비개발) 입력 부담 과다, 전환 기간 동안 페이지가 오히려 비어 보임.

### 방안 B — 본문 자동 서식 + 최소한의 새 칸 (권장)
- 본문 표기법을 파서가 해석해 섹션 카드·목록·경고·표·흐름 그림으로 렌더. 원님 추가 입력 0으로 14개 전부 개선.
- 자동으로 못 만드는 것만 새 칸: 요금 방식+숫자(합계 계산), 참가 연령·인원·출발 안내(요약 타일), 진행 순서(흐름 없는 투어용), 공통 안내 켜기.
- 새 칸이 비어 있으면 본문에서 추출(연령·흐름) → 그것도 없으면 블록을 숨긴다.
- 단점: 파서 규칙이 운영자 표기 습관에 의존 → 규칙 밖 글은 일반 문단으로 안전하게 폴백.

### 방안 C — 현 구조 유지, CSS만 개선
- 장점: 위험 최소. 단점: 정보 위계·예약 동선 문제 미해결.

## 5. 권장 사항 (원님 승인 2026-09-28: "추천대로 진행")
방안 B. 미결이던 결정은 다음 권장값으로 확정:
- **원화 참고 표시**: 표시. "참고 환율 · 1엔 = N원" 라벨 필수, 기존 환율 모듈(1시간 캐시) 재사용.
- **예약 카드**: 날짜 선택은 넣지 않는다(예약 달력 /reserve 와 역할 중복). 요금·출발 시간 표시 + 숫자 요금일 때만 인원 선택·예상 합계. 버튼이 `?tour=&class=&people=` 로 /reserve 에 전달.
- **블로그 투어 연결**: `tourSlug` 선택 칸 추가. 기존 24개 글은 DB를 고치지 않고 제목 키워드로 표시 시점에 추론.
- **공통 안내**: 환불·안전·위약금을 한 곳(`tour_notices`)에서 관리, 투어별로 켜기. 기본값 끔 → 원님이 켜기 전엔 화면 변화 없음. 낚시·요트 환불 규정 내용은 **원님 결정 사항**으로 남김.
- **캘린더 통합(운영 보드+일정·휴무)**: 이번 범위 제외 — 예약 업무 핵심 화면이라 별도 작업으로 분리.
- **방문자 카운터**: 쿠키 없이 (IP+브라우저+날짜) HMAC 해시로 하루 1회 집계. IP 원문은 저장하지 않음. 누적 = 일별 방문자 합계.

## 10. 배포·롤백 절차 (원님 요청 2026-09-28: "맘에 안 들면 롤백 가능하게")

### 10.1 복원 지점
- git 태그 `before-ui-redesign-2026-09` = 개편 직전 운영 코드(main `570d738`). GitHub 에도 올려 둔다.
- PR 은 **merge commit 으로 머지**(squash 금지) → 개편 전체가 머지 커밋 1개로 묶여 한 번에 되돌릴 수 있다.

### 10.2 배포
1. 브랜치 `feat/ui-redesign-2026-09` 푸시 → PR 생성 → Vercel 이 미리보기(Preview) 주소를 자동 발급.
2. 미리보기에서 공개 페이지(투어 상세·블로그·예약) 확인.
   - 제약: `ADMIN_SESSION_SECRET` 이 Production 에만 있어 **미리보기에서는 어드민 로그인 불가**(fail-closed).
   - 미리보기도 운영 Supabase 를 쓴다 → 미리보기에서 예약 문의를 보내면 실제 문의로 저장된다.
3. PR 머지 → Vercel 이 main 을 운영(okinity.com)에 자동 배포(약 1분). 방문자 집계는 이때부터 시작.
4. 운영에서 어드민 확인: 오늘 대시보드, 투어 1개를 **내용 변경 없이** 저장 → 공개 페이지가 그대로인지.

### 10.3 롤백
| 방법 | 속도 | 하는 법 | 주의 |
|---|---|---|---|
| A. Vercel 즉시 롤백 | 수 초 | Vercel → okinity → Deployments → 머지 직전 Production 배포 → Instant Rollback | 코드는 그대로라 이후 main 에 새로 올린 변경은 자동 반영되지 않음(자동 반영이 꺼짐). 고친 뒤 대시보드에서 다시 Promote 필요 |
| B. 코드 되돌리기(영구) | 약 3분 | `git revert -m 1 <머지 커밋>` → PR → 머지 → 자동 배포. Claude 에게 "롤백해줘" | 기록이 남는 정석. 나중에 다시 적용하려면 revert 를 revert |

급하면 A 로 먼저 되돌리고, 결정되면 B 로 코드까지 정리한다.

### 10.4 롤백 시 데이터
- 예전 코드는 새 필드를 모르고 무시한다(zod 기본 동작) → 롤백해도 모든 페이지가 정상.
- 단, **롤백 상태에서 어드민으로 투어·블로그를 다시 저장하면** 그 항목의 새 필드(요금 방식·진행 순서·요약 타일·공통 안내 켜기·블로그 투어 선택)는 지워진다. 본문·사진·가격 글은 보존.
- `tour_notices` 키와 `site_visits` 테이블은 예전 코드가 쓰지 않으므로 그대로 남는다(재적용 시 이어서 사용).
