# GEO 2단계 — 블로그를 AI 답변 근거로 (2026-11-18)

GEO 점검 2번 "블로그 글이 근거로 쓰이기 어렵다"를 원님 인터뷰로 방향을 정해 고친다. 점검 3번(블로그·공지
hreflang 오류)도 같은 파일이라 함께 처리한다. 선행: 20261118-GEO-회사정보-일관성.md

## 1. 현황 분석 (운영 실측, 공개 글 34개)
- 본문 글자 0자 25개, 최대 138자. 사진 120장·영상 37개(본문 사진 alt 는 "제목 사진 n"으로 이미 있음 —
  점검 때 "11장 중 6장 alt 없음"은 다른 글 썸네일·투어 커버(장식, alt="" 정상)였다. 정정).
- 화면·검색 제목이 "푸른동굴 투어" 등으로 반복(입력 제목의 6자리 날짜는 displayTitle 이 뗀다).
- 본문이 없으면 meta description 이 비고(excerptOf 빈 값), 작성자 표시·구조화 데이터 없음.
- 블로그·공지는 한국어 전용(EN/JA 주소는 홈으로 307)인데 `localeAlternates` 가 en/ja hreflang 을 선언.

## 2. 문제 정의
AI 가 인용하는 건 현장 사실(장소 변경 이유·바다 상태·수온·시야·만난 생물). 지금 글에는 그게 없다.
검색 신호(제목 중복·빈 요약·작성자 없음·잘못된 hreflang)도 약하다.

## 3. 해결 방안
- 콘텐츠: (a) 30초 선택형 칸 (b) 2~3분 짧은 글 (c) 추가 없음(코드만)
- 지난 글: (a) 새 글부터 + 코드 보완 (b) 최근 몇 개 보강 (c) 전부 보강

## 4. 트레이드오프
- (b) 짧은 글은 가장 풍부하지만 바쁜 날 빠지기 쉽다 → 질문형 안내(placeholder)로 쓰는 시간을 줄인다.
- 지난 글을 기억으로 보강하면 부정확한 현장 정보가 생긴다 → 내용은 지어내지 않고 형식만 보완.

## 5. 권장 사항 (원님 결정)
목적=새 손님 신뢰·홍보. 작성자=포뇨강사(투어 후 휴대폰/PC). 2~3분 짧은 글 + 질문형 안내.
지난 글은 코드 보완만. 글마다 "포뇨강사" 표시. 검색 제목에만 날짜. 블로그는 이번엔 한국어만.

## 6. 구현 계획
1. `src/lib/blog.ts` — `koDateLabel`(YYYY-MM-DD → 2026년 11월 5일), `blogSeoTitle`(제목 + 날짜),
   `blogDescription`(본문 요약, 없으면 날짜·투어명·사진/영상 수로 만든 문장), `BLOG_WRITING_GUIDE`. 테스트 먼저.
2. `src/lib/structured-data.ts`(신규, 순수) — `representativePerson(locale)`(홈과 공용),
   `blogPostingJsonLd(...)`(headline·datePublished·author=대표 @id·publisher=사업체 @id·about=투어·image 절대 URL).
3. `src/lib/seo.ts` — `koOnlyAlternates(path)`: canonical·hreflang 을 ko·x-default 만.
   블로그 목록·글, 공지 목록·글에 적용.
4. 블로그 글 페이지 — 검색 제목·요약, 작성자 "포뇨강사"(소개 페이지 링크), 사진 alt 에 날짜, BlogPosting JSON-LD.
5. 어드민 블로그 편집기 — 본문 칸 placeholder 를 질문형 안내로.
6. 홈 JSON-LD 의 대표 Person 을 공용 함수로 교체(동작 동일).

### 변경 영향
- 지난 글 34개: 검색 제목·요약·구조화 데이터 자동 개선(내용 변경 없음, DB 쓰기 없음).
- 공지·블로그 hreflang: en/ja 대체 주소 선언 제거(사이트맵과 일치).
