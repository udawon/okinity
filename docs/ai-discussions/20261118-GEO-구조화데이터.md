# GEO 4단계 — 구조화 데이터(회사·투어·소개) (2026-11-18)

기준 글 체크리스트 4번 "구조화 데이터는 화면과 일치". AI·검색이 업체·상품·사람을 같은 대상으로 묶고 숫자를 인용하게.

## 1. 현황 분석
- 홈: LocalBusiness(나하 주소·카카오·라인) + 대표 Person. description 은 한국어 고정(EN/JA 에서도).
- 블로그: BlogPosting(PR #65). 투어 상세·소개: 구조화 데이터 없음.
- 구글 지도 등록 정보: 이름 OKINITY, 분류 travel_agency, 주소 宜野湾市 真志喜 4-18-1(샵), 별점 5.0(4건).
- 공식 인스타그램(okinity_official)이 사이트 어디에도 없음.

## 2. 문제 정의
- 사이트(나하=사업자 등록지)와 구글 지도(기노완=샵) 주소가 달라 AI 가 같은 업체로 묶지 못할 수 있음.
- 투어 가격·자격이 화면에는 있지만 기계가 읽는 형태가 아님 → "체험다이빙 가격 얼마야?" 류 질문에 인용되기 어려움.
- EN/JA 페이지의 업체 설명이 한국어.

## 3. 해결 방안 / 4. 트레이드오프 (원님 인터뷰)
| 항목 | 선택지 | 결정 |
|---|---|---|
| 주소 | 나하로 통일 / 기노완으로 통일 / 그대로 | 그대로(나하=등록지·기노완=샵). 구조화 데이터는 화면과 같은 나하 + 구글 지도 링크(hasMap·sameAs)로 연결. 좌표는 넣지 않음(샵 좌표↔나하 주소 어긋남) |
| 공식 채널 | — | 카카오·라인 + 인스타그램. 인스타그램은 하단에도 표시 |
| 가격 | 시작 가격+문장 / 문장만 / 없음 | 시작 가격 + 화면 문장 그대로. 요트·낚시는 AI용에만 "상담 요망"(화면 금액은 그대로) |
| 펀다이빙 | — | 화면 가격을 "1인 24,000엔~ (2회 다이빙 기준, 다이빙 포인트에 따라 달라집니다)"로(운영 DB) |
| 요금 확정 안내 | 화면+AI / AI만 / 없음 | 없음 — 상담 확정은 원래 구조라 적지 않음. "~부터"로 확정가 아님이 전달됨 |
| 후기 별점 | — | 넣지 않음(구글 정책: 다른 사이트 후기를 구조화 데이터로 옮기지 말 것) |

## 5. 권장 사항 / 6. 구현 계획
1. `lib/structured-data`(순수): businessJsonLd(TravelAgency — 구글 분류와 일치), touristTripJsonLd, aboutPageJsonLd, firstYenAmount, tourOffer.
2. 홈: 업체 설명을 언어별 meta.description 으로, 공개 투어 목록(hasOfferCatalog)으로 투어 페이지와 @id 연결.
3. 투어 상세: TouristTrip(이름·설명·사진·제공자·가격). 시작 가격 = 화면 카드와 같은 규칙(1인 요금 숫자 → 없으면 가격 문장의 첫 금액).
4. 소개: AboutPage + 대표 Person(자격 = 화면의 자격 목록, 사진).
5. 하단: 인스타그램 링크(ko/en/ja).
6. 운영 DB: tour:fun-dive price(한국어) 수정 → 원님 "번역 맞추기".
