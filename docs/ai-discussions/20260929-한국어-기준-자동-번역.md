# 한국어 기준 자동 번역 (2026-09-29)

## 1. 현황 분석
- 언어별 콘텐츠는 `site_content`의 `{key}`(ko)와 `{key}:en`·`{key}:ja`에 **통째 복사본**으로 저장된다.
  - 대상: 투어 상세, 낚시 클래스, 소개, 투어 공통 안내, 갤러리 캡션.
- 한국어를 고쳐도 번역본은 그대로다.
  - E2E 점검(20260929-어드민-서비스-연동-E2E-점검.md) 결과, 11개 투어 전부 한국어가 번역본보다 최신이었다.
  - EN/JA 낚시 가격이 최대 ¥200,000 낮게 표시됐다.
- 갤러리는 어드민이 한국어만 저장하는데, EN/JA 페이지는 7월에 복사한 번역본을 계속 읽는다.

## 2. 문제 정의
원님 결정: **"번역은 항상 한국어를 기준으로"**, 방식은 **한국어 저장 시 자동 번역**.

## 3. 해결 방안
- **A. 자동 동기화(채택)**
  - 한국어를 저장하면 서버가 EN/JA 번역본을 한국어 구조로 다시 만든다.
  - 텍스트 칸 중 바뀐 것만 Claude API로 번역한다.
- **B. 번역 버튼 + 검토**: 원님이 선택하지 않음.
- **C. 세션마다 수동 번역**: "항상"을 만족하지 못함.

## 4. 설계

### 구조와 번역 범위
- 번역본 = 한국어 문서 복제 + 번역 대상 경로만 번역 텍스트로 교체.
- 사진·요금 숫자·공개 여부·옵션 key·순서는 항상 한국어와 같다. 그래서 언어별로 어긋날 수 없다.

### 번역 대상 경로 (`lib/content-sync`)
| 콘텐츠 | 경로 |
|---|---|
| 투어 | `summary`, `duration`, `age`, `people`, `startNote`, `price`, `priceMiddle`, `priceLuxury`, `included`, `body`, `steps[].name`, `steps[].time`, `options[].name`, `options[].description` |
| 낚시 클래스 | `middle.description`, `luxury.description` |
| 소개 | `eyebrow`, `title`, `intro`, `body`, `strengths[].title`, `strengths[].desc`, `instructorName`, `instructorRole`, `instructorCerts`, `instructorBody` |
| 공통 안내 | `refund.title`, `refund.body`, `safety.title`, `safety.body` |
| 갤러리 | `items[].caption` |

### 번역 기억과 동기화 규칙
- **번역 기억(원문 지도):** `translation:{key}:{locale}` = `{ src: { 경로: 번역할 때 쓴 한국어 원문 } }`.
- **재사용:** 새 한국어 원문이 기억에 있으면 기존 번역을 그대로 쓴다. 순서를 바꾸거나 단계를 끼워 넣어도 재번역하지 않는다.
- **번역 호출:**
  - 기억에 없는 원문만 번역한다.
  - 한글이 없는 글(시간·영문 선박명 등)과 빈 글은 그대로 복사한다.
- **번역 실패·키 없음:**
  - 기존 번역이 있으면 유지하고, 새 칸은 한국어로 둔다.
  - 원문 지도를 갱신하지 않으므로 해당 칸은 "번역 필요"로 남는다.
  - 한국어 저장 자체는 절대 막지 않는다.
- **사람이 고친 번역:**
  - EN/JA 탭에서 저장하면, 바뀐 칸의 원문 지도를 현재 한국어로 기록한다.
  - 해당 한국어가 다시 바뀌기 전까지 유지된다.
- **기존 번역본(원문 지도 없음):**
  - 첫 동기화 때 전부 재번역한다.
  - 어드민 "번역 맞추기" 버튼으로 한 번에 처리한다.

### 번역 호출과 저장 흐름
- **번역 호출:**
  - Claude Messages API(`claude-sonnet-5`, `TRANSLATE_MODEL`로 변경 가능).
  - 문서당·언어당 1회 요청하고 EN/JA는 병렬로 보낸다.
  - JSON으로 응답받고 id를 검증한다. 누락이 있으면 1회 재시도한다.
- **문체 지침(메모리):**
  - EN: 미국식 마케팅체. 강사명은 Beomyoung Heo / Instructor Ponyo.
  - JA: です・ます 관광업 표준. 강사명은 ホ・ボミョン.
  - 금액·숫자·URL은 그대로 두고, 엔은 ¥(EN)·円(JA)으로 쓴다.
- **저장 흐름:**
  - 한국어 저장 성공 → 동기화를 동기로 실행(관리 페이지 `maxDuration = 60`) → 결과를 저장 메시지에 표시(예: "영어·일본어 자동 번역 3칸").
- **상태 표시:**
  - 어드민 투어 목록에 언어별 "최신 / N칸 번역 필요"를 보여준다.
  - "번역 맞추기" 버튼으로 투어별 또는 전체를 처리한다.

## 5. 트레이드오프
- 번역 품질은 사람 검수 없이 공개된다. 문체 지침과 금액 보존 규칙으로 위험을 줄인다. 틀린 곳은 EN/JA 탭에서 고치면 유지된다.
- 한국어 저장이 5~20초 느려질 수 있다. 번역한 칸이 많을 때만 해당한다.
- API 비용이 든다. 바뀐 칸만 번역하므로 저장 1회당 소액이다.
- 필요한 환경 변수: `ANTHROPIC_API_KEY`(Vercel, Sensitive). 없으면 자동 번역은 꺼지고 구조·숫자 동기화만 된다.

## 6. 구현 계획
1. `lib/content-sync.ts`(순수): 경로 추출·계획·조립·상태 계산 + 테스트
2. `lib/translate.ts`: 프롬프트·응답 파싱(순수, 테스트) + API 호출
3. `lib/content-sync-server.ts`: 읽기·번역·쓰기
4. 저장 액션 연결(투어·낚시 클래스·소개·공통 안내·갤러리)과 EN/JA 수동 저장 기록
5. 어드민 상태 표시와 "번역 맞추기"
6. 샌드박스 E2E(가짜 번역 API) → 배포 → 원님 키 등록 후 전체 번역 맞추기

### 검증
- 단위 테스트 162개 통과, tsc·build 통과.
- 샌드박스 E2E(가짜 Supabase + 가짜 번역 API, 운영 DB·실제 API 미사용) 29/29 통과.
  - 번역 맞추기 전체 16개 콘텐츠(EN·JA 32회 호출), 사진·옵션 key·요금 숫자·단계 수 = 한국어.
  - 한국어 한 칸 수정 → 그 칸만 번역 요청.
  - EN 탭에서 고친 요약은 다음 한국어 저장에도 유지.
  - 번역 실패 → 한국어는 저장, EN은 이전 번역 유지, 경고 유지, 목록에 "번역 필요 2칸".
  - 갤러리 설명 번역 → 공개 /ja/gallery 반영.
- 키 없는 서버: 한국어 저장 정상, EN/JA 미변경, API 호출 0회, 경고 표시, 번역 맞추기 버튼 비활성.
- 공개 페이지 126개 크롤: 오류·가로 넘침·깨진 링크 0.

### 알려진 한계
1. **EN/JA 탭에서 단계·옵션을 추가/삭제하면** 다음 한국어 저장 때 한국어 구조로 되돌아간다. 구조는 한국어 탭에서만 바꾼다.
   - 사람 번역 기록은 위치(경로) 기준이라, 구조를 바꾼 EN 저장은 기록이 어긋날 수 있다.
2. **홈 화면 문구는 대상이 아니다.** Hero·후기·신뢰 배지·투어 카피는 한국어 전용 어드민 값이고, EN/JA는 고정 번역(i18n)을 쓴다. 블로그·공지는 한국어 전용이다.
3. 번역 품질은 사람 검수 없이 공개된다. 금액·숫자 보존은 프롬프트 규칙에 의존하므로, 운영 첫 번역 후 가격 칸은 직접 확인한다.
