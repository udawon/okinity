# 투어 상세 다중 사진 스와이프 갤러리 (요트크루징 럭셔리/미들 포함)

## 1. 현황 분석

### 1.1 현재 상태

- 요트크루징은 럭셔리(`luxury-yacht-cruise`)/미들(`middle-yacht-cruise`) 2개 slug로 나뉘며, 별도 페이지 없이 **전 투어 14종이 공유하는 상세 페이지** `src/app/[locale]/tours/[slug]/page.tsx` 하나로 렌더된다.
- 상세 이미지는 **대문 사진 1장**: `TourDetailSchema.heroImage`(단일 string, `src/lib/tour.ts:107`) → 페이지 89–98줄에서 `<img>` 1개로 표시.
- 데이터는 `site_content` key-value 테이블의 `tour:{slug}` 키(jsonb). en/ja는 `:en`/`:ja` 접미사 키에 통째로 저장되고, 조회는 로케일 키 우선 → 없으면 ko **값 전체** 폴백(`src/lib/site-content.ts:55-60`).
- 어드민 `src/components/admin/TourEditor.tsx` 89–100줄에 `MediaInput` 1개("상단 이미지"). 업로드 인프라는 완비 상태 — 브라우저에서 WebP 압축 후 Supabase Storage `media` 버킷에 서명 URL로 직행 업로드(`src/lib/upload-client.ts`), 공개 URL은 `/cdn/{path}` 프록시로 1년 캐시.
- 슬라이더 외부 라이브러리 없음. 자체 구현 선례 2개:
  - 스와이프 캐러셀: 홈 `ActivitiesSection`(`src/components/OceanHome.tsx:504-620`) — `overflow-x-auto` + `snap-x snap-mandatory` + 화살표 + reduced-motion 연동.
  - 이미지 배열 어드민 편집: `src/components/admin/GalleryForm.tsx` — 추가/삭제/↑↓ 정렬 + `MediaInput`.
- `heroImage`의 다른 소비처는 어드민 투어 목록의 "작성됨" 판정 1곳뿐(`src/app/admin/tours/page.tsx:32`). OG 이미지·홈 카드에는 미사용.

### 1.2 문제점

- **문제 1 — 스키마가 사진 1장만 허용**: `heroImage: string` 단수라 여러 장을 넣을 자리가 없다. 심각도: 높음(요구사항 자체 불가).
- **문제 2 — 어드민도 1장 입력**: `TourEditor`에 `MediaInput` 1개뿐. 심각도: 높음.
- **문제 3 — 이미지가 언어별 키에 갇힘**: `heroImage`가 언어별 값에 포함돼, ko에서 사진을 바꿔도 en/ja 키가 이미 존재하면 옛 사진이 남는다. 사진 여러 장이 되면 3개 언어 × N장 관리로 운영 부담이 배가된다. 심각도: 중간.
- **문제 4 — 미들 요트는 코드 기본값 부재**: `TOUR_DETAIL_DEFAULTS`(`src/lib/tour.ts:139-152`)에 `luxury-yacht-cruise`만 있어, 미들은 어드민 저장 전까지 "준비 중"으로 노출. 심각도: 낮음(운영으로 해소 가능).

## 2. 목표

### 2.1 달성 목표

- 투어 상세 페이지에서 사진 여러 장을 **좌우 스와이프**(모바일 터치 네이티브)로 넘겨볼 수 있다. 자동 넘김 포함.
- 어드민에서 투어별 사진을 **여러 장 업로드·삭제·순서 변경**할 수 있다.
- 기존에 저장된 `heroImage` 데이터는 마이그레이션 없이 그대로 표시된다(하위 호환).

### 2.2 성공 기준

- 사진 2장 이상 등록 시: 스와이프 동작 + 도트 인디케이터 + (데스크톱) 화살표 + 5초 자동 넘김.
- 사진 0~1장 투어: 기존과 **픽셀 단위 동일**하게 보임(도트·화살표 미노출) — 나머지 12개 투어 무영향.
- `prefers-reduced-motion` 사용자에게 자동 넘김 없음. 사용자가 터치/클릭하면 자동 넘김 정지(WCAG 2.2.2).
- ko에서 사진 교체 시 en/ja 페이지에 즉시 반영(재저장 불필요).
- `npm run typecheck`·`lint` 통과, 신규 npm 의존성 0.

## 3. 해결 방안

### 3.1 결정 A: 데이터 모델 — `images` 배열 추가 방식

#### 옵션 A-1: `images: string[]` 추가, `heroImage`는 하위 호환 폴백으로 유지 (권장)

##### 현재 코드 (`src/lib/tour.ts:105-113`)

```ts
export const TourDetailSchema = z.object({
  summary: z.string().default(''),
  heroImage: z.string().default(''), // 상세 상단 이미지 URL
  duration: z.string().default(''),
  ...
});
```

##### 개선 코드

```ts
export const TourDetailSchema = z.object({
  summary: z.string().default(''),
  heroImage: z.string().default(''), // (구) 단일 대문 — images 폴백·목록 썸네일용으로 유지
  images: z.array(z.string()).default([]), // 상세 갤러리 사진 URL 목록(첫 장 = 대표)
  duration: z.string().default(''),
  ...
});

/** 표시용 사진 목록 해석 — images 우선, 비어 있으면 heroImage 1장 폴백. */
export function tourImages(detail: TourDetail): string[] {
  if (detail.images.length) return detail.images;
  return detail.heroImage ? [detail.heroImage] : [];
}
```

- 장점: DB 마이그레이션 0건 — 기존 `tour:*` 값은 zod `default([])`로 그대로 파싱되고 `heroImage` 폴백으로 계속 표시됨. 저장 시 `heroImage = images[0]`을 동기화하면 어드민 목록의 "작성됨" 판정(`admin/tours/page.tsx:32`)도 무수정 동작.
- 단점: 필드 2개가 공존해 스키마가 다소 지저분함(주석으로 역할 명시 필요).

#### 옵션 A-2: `heroImage` 제거, `images`로 통합 + DB 마이그레이션

- 장점: 스키마 단일화.
- 단점: 운영 DB의 모든 `tour:*`(+`:en`/`:ja`) 키 재작성 스크립트 필요, 롤백 곤란, `TOUR_DETAIL_DEFAULTS`·어드민 목록 판정 등 소비처 동시 수정. 이득 대비 리스크 과다.

**캡션 여부**: `GalleryForm`은 `{image, caption}` 객체지만, 투어 갤러리는 **캡션 없는 `string[]`** 로 간다. 캡션은 언어 종속 텍스트라 아래 3.3 "이미지 언어 중립" 결정과 충돌하고, 필요해지면 zod로 하위 호환 파싱하며 객체 배열로 진화 가능.

### 3.2 결정 B: 갤러리 UI 구현 방식

#### 옵션 B-1: 자체 scroll-snap 캐러셀 (신규 `TourPhotoCarousel.tsx`) (권장)

##### 현재 코드 (`src/app/[locale]/tours/[slug]/page.tsx:89-98`)

```tsx
{showDetail && detail.heroImage && (
  <div className="mt-6 overflow-hidden rounded-card border border-white/10 ...">
    <img src={cdnMedia(detail.heroImage)} alt={tourName} className="aspect-[16/9] w-full object-cover" />
  </div>
)}
```

##### 개선 코드 (핵심 구조)

```tsx
// src/app/[locale]/tours/[slug]/page.tsx — 서버 컴포넌트는 교체만
{showDetail && images.length > 0 && (
  <TourPhotoCarousel images={images.map(cdnMedia)} alt={tourName} />
)}

// src/components/TourPhotoCarousel.tsx (신규, 'use client')
// - 트랙: overflow-x-auto + snap-x snap-mandatory → 모바일 스와이프는 브라우저 네이티브
// - 슬라이드: aspect-[16/9] w-full snap-center, 첫 장 eager + fetchPriority="high", 나머지 loading="lazy"
// - scroll 이벤트로 현재 인덱스 추적 → 도트 인디케이터(탭 이동 겸용)
// - lg 이상에서 좌우 글래스 화살표(OceanHome.tsx:601-619 패턴 재사용)
// - 자동 넘김: 5초 setInterval + scrollTo({behavior:'smooth'}) / 마지막 장에서 첫 장 복귀
//   · useStableReducedMotion() true면 비활성
//   · pointerdown·wheel 등 사용자 개입 시 영구 정지, document.hidden 동안 일시 정지
// - images.length === 1이면 인디케이터·화살표·자동 넘김 모두 숨김(기존과 동일한 정적 1장)
```

- 장점: 신규 의존성 0(프로젝트의 기존 정책·선례와 일치), 모바일 스와이프가 CSS 네이티브라 JS 부담 최소, 검증된 자체 패턴(`OceanHome.tsx:504-620`) 재사용.
- 단점: 무한 루프·관성 미세 튜닝 같은 고급 동작은 직접 구현 몫(이번 요구 범위에는 불필요).

#### 옵션 B-2: 외부 라이브러리 (embla-carousel-react + autoplay 플러그인)

- 장점: 루프·자동재생·드래그 물리 기성품(~7KB gzip).
- 단점: 첫 슬라이더 의존성 도입 — 현재 캐러셀 2곳(홈·신규)이 서로 다른 구현이 되거나 홈까지 재작성해야 일관성 유지. 요구 기능(스와이프+도트+자동)이 단순해 라이브러리가 과함.

#### 옵션 B-3: 정적 그리드 + 라이트박스

- 장점: 구현 최소.
- 단점: "스와이프로 넘겨보기"라는 요구 자체를 충족하지 못함 → 탈락.

### 3.3 결정 C: 다국어 — 이미지의 저장·조회 소스

#### 옵션 C-1: 이미지는 ko 키에서만 해석(언어 중립 자산) (권장)

##### 현재 코드 (`src/app/[locale]/tours/[slug]/page.tsx:64-65`)

```ts
const value = await getLocalizedSiteContent(CONTENT_KEYS.tour(slug), locale);
const detail = resolveTourDetail(slug, value);
```

##### 개선 코드

```ts
// getLocalizedSiteContent는 내부적으로 이미 [ko키, 로케일키] 2개를 한 쿼리로 조회한다
// (site-content.ts:55-60). 같은 방식으로 두 값을 모두 받아:
//   텍스트(summary/body 등) = 로케일 값(없으면 ko 폴백) — 기존 동작 유지
//   images = 항상 ko 값에서 해석 — 사진은 언어 중립
const key = CONTENT_KEYS.tour(slug);
const map = await getSiteContentMap([key, localizedContentKey(key, locale)]);
const detail = resolveTourDetail(slug, map[localizedContentKey(key, locale)] ?? map[key] ?? null);
const images = tourImages(resolveTourDetail(slug, map[key] ?? null));
```

- 장점: 사진을 ko 탭 한 곳에서만 관리(3개 언어 3중 관리 제거), ko 사진 교체가 en/ja에 즉시 반영. DB 쿼리 수 증가 없음(기존도 2키 조회).
- 단점: "이미지만 ko" 규칙이 코드에 암묵적으로 생김 — `tour.ts` 주석과 어드민 en/ja 탭 안내문으로 명시 필요.

#### 옵션 C-2: 현행 유지(언어별 키에 이미지도 저장)

- 장점: 조회 로직 무변경.
- 단점: 문제 3 그대로 — en/ja 키가 존재하는 투어는 ko에서 사진을 갈아도 반영 안 됨. 사진 N장 시대엔 운영 사고(언어별 사진 불일치) 확률이 커짐.

### 3.4 어드민 — 사진 목록 편집 (공통, 옵션 아님)

`TourEditor.tsx` 89–100줄의 "상단 이미지" `MediaInput` 1개를 **사진 목록 편집 섹션**으로 교체. `GalleryForm.tsx`의 추가/삭제/↑↓ 패턴을 그대로 옮기되:

```tsx
const [images, setImages] = useState<string[]>(
  detail.images.length ? detail.images : detail.heroImage ? [detail.heroImage] : []
); // 기존 1장 데이터를 편집 시작 시점에 배열로 승격

{images.map((url, i) => (
  <MediaInput key={i} prefix="tours" accept="image/*"
    value={url}                       // ★ controlled 모드 필수
    onChange={(u) => patch(i, u)} />
))}
```

- **`MediaInput`은 반드시 controlled(`value=`) 모드**: 인덱스 key 목록에서 비제어를 쓰면 ↑↓ 이동 시 내부 state가 남아 엉뚱한 미디어가 보이는 버그가 명시돼 있음(`MediaInput.tsx:30-36` 주석). 기존 `GalleryForm`은 `defaultUrl`(비제어)을 쓰고 있어 같은 잠재 버그 보유 — 이번 신규 코드는 controlled로 작성(GalleryForm 수정은 범위 외, 후속 과제로 기록).
- 첫 번째 사진에 "대표" 배지 표시(목록 썸네일·폴백에 쓰임을 안내).
- **ko 탭에서만 편집 노출**, en/ja 탭에서는 "사진은 한국어 탭에서 관리합니다(모든 언어 공통)" 안내문으로 대체(결정 C-1 연동).
- 저장 액션 `saveTour`(`src/app/admin/tour-actions.ts:30-47`)에서 `heroImage: images[0] ?? ''` 동기화 — zod 파싱은 스키마 확장만으로 통과.
- 안내문에 권장 장수(5~8장) 명시 — 성능 가드(7.1 리스크 1 연동).

## 5. 권장 사항

### 5.1 추천 옵션

**A-1 + B-1 + C-1**: `images: string[]` 배열 추가(heroImage 폴백 유지) + 자체 scroll-snap 스와이프 캐러셀(자동 넘김 포함) + 이미지는 ko 키 단일 소스.

### 5.2 근거

- 마이그레이션·신규 의존성·신규 테이블 전부 0 — 기존 업로드 인프라(WebP 압축 → Supabase Storage → `/cdn` 1년 캐시)와 자체 캐러셀 선례를 그대로 조립하는 구성이라 변경 반경이 가장 작다.
- 사진은 언어 중립 자산이므로 ko 단일 소스가 운영 실수(언어별 사진 불일치)를 구조적으로 차단한다.
- 자동 넘김은 "여러 사진을 보여주고 싶다"는 목적에 부합하되, 사용자 개입 시 영구 정지 + reduced-motion 비활성으로 접근성 기준(WCAG 2.2.2)을 지킨다.
- 전 투어 공통 컴포넌트이므로 요트 2종에 사진을 채우는 즉시 적용되고, 나머지 투어는 사진 1장이면 기존 외형 그대로다.

## 7. 리스크 및 고려사항

### 7.1 잠재적 리스크

- **리스크 1 — 페이지 무게 증가**: 사진 N장이면 전송량 N배(2026-07 성능 리뷰에서 홈 27.6MB 지적 이력). 대응: 첫 장만 eager + 나머지 `loading="lazy"`, 업로드 시 WebP 압축(기존), 어드민에 권장 장수(5~8장) 안내.
- **리스크 2 — 자동 넘김 UX 역효과**: 사진을 보는 중에 넘어가면 짜증 유발. 대응: 사용자 개입(터치·휠·화살표·도트) 즉시 영구 정지, reduced-motion·백그라운드 탭에서 비활성.
- **리스크 3 — 배열 편집 순서 버그**: 인덱스 key + 비제어 MediaInput 조합의 알려진 함정. 대응: controlled 모드 강제(3.4). 기존 `GalleryForm`의 동일 잠재 버그는 후속 과제로 분리.
- **리스크 4 — 전 투어 공통 영향**: 14종 전체가 같은 페이지 — 사진 1장(=기존 데이터) 투어가 조금이라도 달라 보이면 회귀. 대응: 1장일 때 캐러셀 부속 UI 전부 미노출 + QA에서 비요트 투어 1종 확인.
- **리스크 5 — 미들 요트 기본값 부재**: 사진을 넣어도 published 저장 전엔 "준비 중". 대응: 운영 후속(6단계 7)으로 처리, 코드 기본값 추가는 불필요.

### 7.2 의존성

- 신규 npm 의존성 없음. Supabase Storage `media` 버킷·`/cdn` 프록시·`MediaInput`/`upload-client` 기존 인프라 재사용.
- 테스트 인프라 부재(프로젝트에 테스트 러너 없음) — `tourImages()` 등 해석 로직을 순수 함수로 분리해 두고, 검증은 typecheck + lint + 브라우저 QA로 수행.
